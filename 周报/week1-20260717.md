## 二、问题与解决

1. **问题1**：独热编码中对输入的转置操作——张量的形状为什么是 `(L, N, H)` 而非 `(N, L, H)`？
   - *现象*：之前使用 PyTorch 内置 RNN 模型时，知道有 `batch_first` 参数可以切换维度顺序，但默认输入/输出形状是 `(L, N, H)`（时间步在前，批次在后），一直没有深究原因。
   - *理解*：这次复现从零开始部分代码时发现：
     1. 数据准备阶段——先按批次划分语料，再将各批次拼接，自然形成以时间步为最外层的结构；
     2. 前向传播阶段——RNN 模型以 L 个时间步逐层循环，每个时间步并行计算当前批次内所有样本。
   - *结论*：`(N, L)` 经独热编码转置后变为 `(L, N, H)`，使每个时间步的循环能直接取出一个 batch 的所有样本，逻辑清晰且实现高效。

2. **问题2**：处理语料时，随机采样和顺序分区两种数据处理方式似乎没什么区别，但实际中随机采样用得更多？
   - *猜测*：随机采样时，不同 batch 之间的序列在原始语料中不一定连续，因此每个 batch 训练前都需要重新初始化 H_0。联想到训练时 loss 曲线往往开头较陡（梯度大），我认为这样能让每次训练都经历一个"梯度较大"的阶段，避免隐状态在长序列上持续累积导致的梯度消失。
   - *待验证*：随机采样是否会引入额外的噪声，影响模型收敛稳定性？

3. **问题3**：学了 GRU 后回头看不理解 LSTM——它的记忆单元 C 和隐状态 H 的作用是否有重叠？两个模型的本质区别在哪？
   - *对比分析*：

     |     | LSTM                              | GRU                               |
     |-----|------------------------------------|------------------------------------|
     | 记忆单元 | **C**（长期记忆，仅经遗忘门调节，不经输出门筛选） | 无独立记忆单元                     |
     | 隐状态  | **H**（短期，经输出门从 C 筛选后输出）    | **H**（同时承担长期和短期记忆职责） |
     | 门控设计 | 遗忘门、输入门、输出门              | 重置门、更新门                     |

   - *结论*：
     - LSTM 中 C 之所以能存储更长内容，是因为它只受遗忘门影响，少了一层输出门的筛选——C 的变化比 GRU 中 H 的变化更慢、更稳定。正因为 LSTM 有 C 保存长期记忆，H 只需要保留更少的内容。
     - GRU 对 LSTM 进行简化，H 需同时兼顾长短记忆，通过更新门 Z 保留 H 中“有用的”旧信息和新信息，丢弃的 H 内容比 LSTM 对 C 做的改动更大。
     - 两个模型解决梯度问题的思路不同，H 承担的责任也不同。
  
4. **问题4**：编码器和解码器值得注意的地方。
   - 前面的RNN都使用独热编码处理输入，构造编码器和解码器部分使用了嵌入层。从 Jupyter 中得到的输出来看，两者都是将 vocab 中的词元转换为向量，独热编码得到的向量过于稀疏，而嵌入层得到的向量信息更紧凑。
   - 编码器使用 RNN 将长度可变的输入序列转换成形状固定的上下文变量 context（RNN 最后一层中最后一时间步的 state），编码器不涉及预测，可以双向。
   - 在解码器中输入是 RNN 上一时间步的输出 y_t-1 和 context 连接得到的，所以解码器中的 RNN 输入维度为 `embed_size + hidden_size` ，在前向传播中就需要广播 context 使其具有和输入具有同样的时间步再进行拼接。
