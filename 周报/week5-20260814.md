  - 核心内容：
    - **PEFT 基本使用**：
      - `LoraConfig` + `get_peft_model()` 将基础模型包装成 PeftModel，通过 `model.print_trainable_parameters()` 查看可训练参数量

    - **PEFT 方法对比**：
      - **Prefix Tuning**：在注意力 K/V 前构造任务相关、可训练的前缀虚拟 token
      - **Prompt Tuning**：只在输入层加入 prompt，简化版前缀微调；模型越大效果越接近全参微调
      - **P-Tuning / P-Tuning v2**：可学习的 virtual token 由 MLP+LSTM 编码生成；v2 在每一层都加并移除重参数化

      - **Adapter Tuning / IA³**：在 Transformer 层中插入 Adapter 结构 / 在输出通道乘可学习向量
    - **LoRA 微调代码实现**：
      - 数据处理：统一字段为 instruction/input/output，构造指令微调 prompt
      - tokenize 与 labels 构造：pad_token 设为 eos_token，labels 中设计掩码用于计算 acc

    - **MLLM 五阶段架构**：
      - **模态编码**：Modality Encoder 将高维原始信号下采样为紧凑的感知特征 $\mathbf{F}_x$
      - **输入投影**：Input Projector 作为语义翻译器，把视觉特征映射到文本语义空间（$\mathbf{P}_x = \text{MLP}(\mathbf{F}_x)$ 或 Cross-Attention），消除模态鸿沟
      - **主干推理**：LLM Backbone 把视觉嵌入作为软提示与文本指令拼接，自回归生成文本及多模态控制信号（隐含层状态）
      - **输出投影 / 模态生成**：Output Projector 把控制信号解码为条件嵌入，交给 Diffusion/VAE 生成目标模态
      - **训练范式**：阶段一冻结编码器与 LLM 只训投影器做模态对齐；阶段二解冻 LLM 做指令微调（全量或 LoRA）

## 二、问题与解决

1. **问题1**：训练时如果不做 labels 掩码处理，loss 会把 prompt 部分也计入，会导致什么？
   - *现象*：若直接把 full_text 的 input_ids 当 labels 训练，token 准确率虚高，但模型实际回复质量较差。
   - *理解*：prompt 内容模型在输入中已经"看见"，预测它是"送分题"，无法反映真实的指令跟随能力；padding 部分则无任何语义意义。
   - *解决*：在 tokenize_fn 中把 prompt 部分的 labels 置为 -100，padding 对应位置也置为 -100，交叉熵损失会自动忽略 -100；compute_metrics 里同样用 `labels != -100` 的 mask 统计准确率。
   - *结论*：labels 的掩码设置是微调正确性的关键——要区分"输入可见但不计损失"和"需要模型预测的标签"这两类位置。

2. **问题2**：`dataset["train"][0]` 与 `dataset[0]["train"]` 两种索引方式有什么区别？
   - *理解*：datasets 库中列（features）是主存储结构，`dataset["train"][0]`（列在前）直接定位列再取行，速度更快；`dataset[0]["train"]`（行在前）逐行访问，写法也可以但效率更低。
   - *延伸*：map 回调返回的字典中，键名在原始数据中不存在时会作为新列加入，键名已存在则会覆盖原有列的值，所以用 map 做字段重命名时直接返回新键名并配合 `remove_columns` 删除旧列即可。

## 1. PEFT 的基本使用

* PEFT 的基本用法和各种适配器的使用都在[HF指南](https://hugging-face.cn/docs/peft/index)可以详细查看。
* 下面是加载模型并使用 Lora 的例子，后续可以使用 Transformers 的 Trainer、Accelerate 或任何自定义的 PyTorch 训练循环来训练模型。

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import get_peft_model
from peft import LoraConfig, TaskType

MODEL_NAME = "/0to1MLLM/models/Qwen1.5-1.8B-Chat"

# 每种 PEFT 方法都由一个 PeftConfig 类定义，该类存储了构建 PeftModel 所需的所有重要参数
peft_config = LoraConfig(task_type=TaskType.CAUSAL_LM, inference_mode=False, r=8, lora_alpha=32, lora_dropout=0.1)

model = AutoModelForCausalLM.from_pretrained(
        MODEL_NAME,
        dtype=torch.bfloat16,
        device_map="auto"
    )

print("原始模型结构")
print(model)

# 使用 get_peft_model() 函数将基础模型和 peft_config 包装起来，以创建 PeftModel。
model = get_peft_model(model, peft_config)
print("LORA 模型结构")
print(model)

print("模型中可训练参数的数量")
model.print_trainable_parameters()
```

## 3. 参数高效微调 PEFT 方法
    
参考[大模型微调技术 - RedHerring的文章 - 知乎](https://zhuanlan.zhihu.com/p/682082440)

### Prefix Tuning（前缀微调）

**核心思想：**
token 之前构造一段任务相关的 virtual tokens 作为 Prefix，然后训练的时候只更新 Prefix 部分的参数，针对不同的模型结构，需要构造不同的 Prefix。

* 针对自回归架构模型：在句子前面添加前缀（Transformer 各层的 attention 的 K/V 前）。
* 针对编码器-解码器架构模型：Encoder 和 Decoder 都增加了前缀。

### Prompt Tuning

**核心思想：**
Prefix Tuning的简化版本，它给每个任务定义了自己的 Prompt，然后拼接到数据上作为输入，但只在输入层加入 prompt tokens，并且不需要加入多层感知机（MLP）进行调整来解决难训练的问题。

* 模型越大，Prompt Tuning 的效果越好，能靠近全参微调。

### P-Tuning

**核心思想：**
P-Tuning（V1）设计了一种连续可微的 virtual token（同Prefix-Tuning类似）。将 Prompt 转换为可以学习的 Embedding 层，并用MLP+LSTM的方式来对 Prompt Embedding 进行一层处理。通过可训练的编码器生成virtual token 再像 Prefix-Tuning 的 Prefix 一样工作，只用于输入层。

* virtual token 仅限于输入层，没有在每一层都加。输入的位置是可选的，不一定是前缀。
* 相比 Prompt Tuning，P-Tuning 不需要人工制作 prompt。

### P-Tuning v2

**核心思想：**
相比 Prompt Tuning 和 P-tuning 的方法， P-tuning v2 方法在每一层加入了 Prompts tokens 作为输入，具体做法基本同Prefix Tuning。

* 移除重参数化的编码器，每个 virtual token 的嵌入向量，就是一个普通的可训练参数
* 针对不同任务采用不同的提示长度。
* 引入多任务学习，先在多任务的Prompt上进行预训练，然后再适配下游任务。
* 回归传统的分类标签范式，而不是映射器。

### LoRA

**核心思想：**
通过低秩分解来模拟参数的改变量，从而以极小的参数量来实现大模型的间接训练。操作如下：

1. 在原始预训练模型（PLM）的参数旁边增加一个旁路 derltaW, 做一个降维再升维的操作, 来模拟所谓的 intrinsic rank，即 derltaW = AB。
2. 训练的时候固定 PLM 的参数 W0, 只训练降维矩阵 A 与升维矩阵 B。而模型的输入输出维度不变, 输出时将 BA 与 PLM 的参数叠加。
3. 用随机高斯分布初始化 A, 用 0 矩阵初始化 B, 保证训练的开始此旁路矩阵依然是 0 矩阵。
4. LoRA训练参数量显著减少，GPU内存需求减少，无额外推理延迟。

LoRA 有许多变种：

| 方法 | 核心思想 | 优点 | 缺点 / 代价 |
| :--- | :--- | :--- | :--- |
| **LoRA** | 冻结 W，只训练低秩矩阵 BA | 简单、稳定、生态成熟 | 需要全精度基座（若不用量化） |
| **QLoRA** | 4bit 量化 W + LoRA | 显存极省，支持大模型 | 实现稍复杂，对框架依赖较大 |
| **AdaLoRA** | 自适应分配 LoRA rank | 在同参数预算下更高性能 | 训练逻辑复杂，主流实现较少 |
| **DoRA** | 分离尺度/方向，只在方向上做 LoRA | 小 rank 时更稳定、更准 | 复杂度高，生态不如 LoRA/QLoRA |
| **LoHa/LoKr** | 哈达玛/克罗内克等结构化低秩更新 | 同参数下表达力更强 | 推理/训练开销略增，实现复杂 |
| **ReLoRA** | 周期性合并 LoRA 并重启 | 对长时间训练更稳定 | 应用场景偏继续预训练，门槛高 |
| **PiSSA** | 基于 SVD 的 LoRA 初始化 | 收敛更快，早期效果好 | 需要额外 SVD 计算，工程更复杂 |

### Adapter Tuning

**核心思想：**
Adapter Tuning 设计了Adapter结构，并将其嵌入Transformer的结构里面，针对每一个Transformer层，增加了两个Adapter结构，分别是多头注意力的投影之后和第二个feed-forward层之后。在训练时，固定住原来预训练模型的参数不变，只对新增的 Adapter 结构和 Layer Norm 层进行微调，从而保证了训练的高效性。

### IA³

**核心思想：**
在注意力和前馈（Feed Forward）的输出通道处乘一个可学习的向量（或标量），等效于给每个通道配备一个乘性因子。

* 实现较为简单，训练参数量极低；理论与实验表明在多任务场景下有高效表现。

## 4. 代码实现 lora 微调

微调的实现

```python
import torch
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    TrainingArguments,
    Trainer,
    default_data_collator,
)
from peft import LoraConfig, TaskType, get_peft_model
from datasets import load_dataset
import logging

logger = logging.getLogger(__name__)

# 准备数据
# 1. 加载数据文件
data_files = {
        "train":"../dataset/alpaca-chinese-dataset/data_v3/alpaca_chinese_part_0.json",
        "validation": "../dataset/alpaca-chinese-dataset/data_v3/alpaca_chinese_part_1.json",
}

# 2. 读取json数据集
# datasets.load_dataset 可以自动解析并根据字典划分
dataset = load_dataset("json", data_files=data_files)

train_dataset = dataset["train"]
val_dataset = dataset["validation"]

# 仅取前10条验证集，防止 eval 太慢
val_dataset = val_dataset.select(range(10))

# 3. 统一字段格式：instruction/input/output
def convert_to_zh_format(example):
    # 如果 zh_input 缺失，默认空字符串
    return {
        "instruction": example["zh_instruction"],
        "input": example.get("zh_input", ""),
        "output": example["zh_output"],
    }

zh_train_dataset = train_dataset.map(convert_to_zh_format, remove_columns=train_dataset.column_names)
zh_val_dataset = val_dataset.map(convert_to_zh_format, remove_columns=val_dataset.column_names)

# 准备模型和Tokenizer、Tokenize函数
# 4. 初始化模型路径和 Tokenizer
MODEL_NAME = "../models/Qwen1.5-1.8B-Chat"
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME, trust_remote_code=True)

# padding 会在 tokenize_fn 中用于构造 labels，需要在 map 数据集前设置好。
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token
    tokenizer.pad_token_id = tokenizer.eos_token_id

def make_prompt(example):
    """构建因果语言建模 prompt: 指令 +（可选输入）+ 回复"""
    if example["input"] is None or example["input"] == "":
        # 无输入时只保留指令
        return f"指令: {example['instruction']}\n回复: "
    # 有输入时拼接输入
    return f"指令: {example['instruction']}\n输入: {example['input']}\n回复: "

def tokenize_fn(example):
    """把单条样本转换成模型输入ID并生成labels"""
    prompt = make_prompt(example)
    full_text = prompt + example["output"] + tokenizer.eos_token

    # tokenizer 返回 input_ids、attention_mask 等
    tokenized = tokenizer(
        full_text,
        truncation=True,
        max_length=1024,
        padding="max_length",
    )

    # 只计算输出部分 loss。prompt 部分不计入损失，设置为 -100。
    prompt_len = len(tokenizer(prompt, truncation=True, max_length=1024)["input_ids"])
    labels = tokenized["input_ids"].copy()
    labels[:prompt_len] = [-100] * prompt_len
    labels = [
        -100 if token_id == tokenizer.pad_token_id else token_id
        for token_id in labels
    ]
    tokenized["labels"] = labels
    return tokenized

# 5. map数据集进行tokenizer处理
zh_train_dataset = zh_train_dataset.map(tokenize_fn, remove_columns=zh_train_dataset.column_names)
zh_val_dataset = zh_val_dataset.map(tokenize_fn, remove_columns=zh_val_dataset.column_names)

# 6. Data Collator: 保留 tokenize_fn 中手动构造的 labels
data_collator = default_data_collator

# 评价指标部分
# 7. 计算 token 准确率（忽略 label=-100）
def compute_metrics(eval_pred):
    logits, labels = eval_pred
    # Trainer 会把模型 GPU 上的 logits 移到 CPU 并转成 numpy 数组后再调用 compute_metrics
    logits = torch.from_numpy(logits)
    labels = torch.from_numpy(labels)
    preds = torch.argmax(logits, dim=-1)
    mask = labels != -100
    if mask.sum().item() == 0:
        return {"token_accuracy": 0.0}
    correct = (preds == labels) & mask
    accuracy = correct.sum().item() / mask.sum().item()
    return {"token_accuracy": accuracy}


# 模型+lora+训练配置部分
# 8. LoRA 参数配置
peft_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    inference_mode=False,
    r=8,
    lora_alpha=32,
    lora_dropout=0.1,
)

# 9. 加载原始因果LM模型
model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    torch_dtype=torch.bfloat16,
    device_map="auto",
)

# 关闭 cache，避免训练时梯度计算和 memory 问题
model.config.use_cache = False

# 10. 包装成 PEFT LoRA 模型
model = get_peft_model(model, peft_config)

# 11. 对齐 token id
if tokenizer.bos_token_id is None:
    tokenizer.bos_token = tokenizer.convert_ids_to_tokens(model.config.bos_token_id)
    tokenizer.bos_token_id = model.config.bos_token_id
if tokenizer.eos_token_id is None:
```

# Part3. MLLMs 架构解构

参考[MM-LLMs: Recent Advances in MultiModal Large Language Models](https://arxiv.org/abs/2401.13601)

## 阶段一：模态编码（Modality Encoding）

- **模块**：Modality Encoder（如 CLIP ViT, ImageBind）
- **功能定位**：将非结构化的高维原始信号（像素空间/时域信号）下采样为紧凑的、富含语义的**感知特征图**。
- **输入定义**：
  - 原始数据张量 $\mathcal{X} \in \mathbb{R}^{B \times C \times H \times W}$（如图像），其中 $B$ 为批大小，$C$ 为通道数，$H, W$ 为空间分辨率。
- **输出定义**：
  - 编码视觉特征 $\mathbf{F}_x \in \mathbb{R}^{B \times N \times D_{enc}}$
  - 其中，$N$ 为视觉令牌（Visual Tokens）数量（取决于 Patch 分割策略，如 $N = H \cdot W / P^2$），$D_{enc}$ 为编码器固有的隐空间维度（例如 CLIP ViT-L/14 中 $D_{enc}=1024$）。

## 阶段二：输入投影（Input Projection / 模态桥接）

- **模块**：Input Projector（如 MLP, Q-Former, ConvResampler）
- **功能定位**：作为**语义翻译器（Semantic Translator）**，将编码器提取的感知特征 $\mathbf{F}_x$ 从视觉空间仿射变换或交叉注意力提炼至大语言模型可理解的**文本语义空间**，旨在消除模态间的表征鸿沟（Modality Gap）。
- **输入定义**：
  - 承接阶段一输出 $\mathbf{F}_x \in \mathbb{R}^{B \times N \times D_{enc}}$。
- **输出定义**：
  - 视觉提示嵌入（Visual Prompt Embeddings）$\mathbf{P}_x \in \mathbb{R}^{B \times M \times D_{llm}}$
  - 注：$M$ 可等于或小于 $N$（例如通过池化或重采样进行令牌压缩，LLaVA-1.5 中 $M=N=576$，Qwen-VL 中压缩至 $M=256$）；$D_{llm}$ 对应主干网络的隐藏层大小（如 LLaMA-3 中 $D_{llm}=4096$）。
  - 其映射关系通常为 $\mathbf{P}_x = \text{MLP}(\mathbf{F}_x)$ 或 $\mathbf{P}_x = \text{Cross-Attn}(\mathbf{Q}, \mathbf{F}_x)$。

## 阶段三：主干推理与认知（Backbone Reasoning）

- **模块**：LLM Backbone（如 LLaMA, Vicuna, Qwen）
- **功能定位**：**多模态理解与知识推理**。将视觉嵌入 $\mathbf{P}_x$ 视为软提示（Soft Prompts），与用户文本指令拼接，利用 Transformer 的自回归机制进行上下文推导，生成包含文本回复及潜在多模态控制信号的混合输出序列。
- **输入定义**：
  - 拼接后的输入序列 $\text{Input}_{seq} = [\text{CLS}] \oplus \mathbf{P}_x \oplus \text{Token}(t_{text})$
  - 其中 $\oplus$ 表示序列维度拼接，$t_{text}$ 为用户输入的指令（Prompt）。
- **输出定义**：
  - 生成两个互补子集：
    1. **离散文本输出** $\mathbf{Y}_{text}$：常规的自然语言回复。
    2. **多模态控制信号** $\mathbf{S}_x \in \mathbb{R}^{B \times L \times D_{llm}}$：即对应 `<img>` 或 `<audio>` 等特殊占位符（Placeholder Tokens）的**隐含层状态（Hidden States）**，用于承载生成非文本内容的语义意图。

## 阶段四：输出投影（Output Projection / 条件解码桥接）

- **模块**：Output Projector（多为 MLP 或 Transformer 解码层）
- **功能定位**：将 LLM 输出的高维抽象控制信号 $\mathbf{S}_x$ 解码映射为低级生成器（Diffusion / VAE）所能识别的**条件嵌入（Conditioning Embeddings）**。
- **输入定义**：
  - 承接阶段三中提取的控制信号 $\mathbf{S}_x \in \mathbb{R}^{B \times L \times D_{llm}}$。
- **输出定义**：
  - 生成器条件特征 $\mathbf{H}_x \in \mathbb{R}^{B \times L \times D_{gen}}$
  - 其中 $D_{gen}$ 对应特定生成模型的文本编码器维度（如 Stable Diffusion 的 CLIP 文本编码器维度 $D_{gen}=768$）。
  - 映射关系表示为 $\mathbf{H}_x = \text{MLP}(\mathbf{S}_x)$。

## 阶段五：模态生成（Modality Generation）

- **模块**：Modality Generator（如 Stable Diffusion, AudioLDM, VQ-VAE）
- **功能定位**：作为**神经渲染器（Neural Renderer）**，以 $\mathbf{H}_x$ 为条件约束，结合随机噪声先验，通过迭代去噪或自回归生成高保真的目标模态数据。
- **输入定义**：
  - 条件嵌入 $\mathbf{H}_x$ 与随机高斯噪声 $\mathbf{z} \sim \mathcal{N}(0, \mathbf{I})$。
- **输出定义**：
  - 最终生成的目标数据 $\hat{\mathbf{y}} \in \mathbb{R}^{B \times C_{out} \times H_{out} \times W_{out}}$（图像/视频帧/音频频谱图）。

## 训练策略与优化范式（Training Paradigm）

鉴于上述模块化的解耦特性，MLLMs 的训练通常遵循以下两阶段范式：

### 阶段一：模态对齐预训练（Alignment Pre-training）
- **目标**：缩小模态鸿沟。
- **策略**：冻结（Freeze）视觉编码器与 LLM 主干，仅更新输入投影器（Input Projector）的参数。训练数据为大规模图文对（Image-Text Pairs），以自动回归下一文本预测（Next Token Prediction, NTP）为损失函数，使 $\mathbf{P}_x$ 的分布逼近文本嵌入（Text Embeddings）。

### 阶段二：指令微调（Instruction Fine-tuning）
- **目标**：激发多模态对话与泛化能力。
- **策略**：保持视觉编码器冻结，解冻（Unfreeze）LLM 主干与输入投影器，使用高质量的指令跟随数据（指令-回答对）进行全量或部分（LoRA）参数更新，使模型具备遵循复杂人类指令并给出精确反馈的能力。
